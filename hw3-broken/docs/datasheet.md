# Datasheet: вопросы об экзопланетах

## Назначение и происхождение

Учебный русскоязычный chat-датасет для дообучения модели отвечать на короткие
фактические вопросы о подтверждённых экзопланетах. Тема выбрана самостоятельно
по поручению владельца работы; отдельное подтверждение уникальности темы у
преподавателя в технических материалах отсутствует.

Источник — публичная таблица **Planetary Systems Composite Parameters
(PSCompPars)** из [NASA Exoplanet Archive](https://exoplanetarchive.ipac.caltech.edu/docs/API_PS_columns.html).
По [документации TAP](https://exoplanetarchive.ipac.caltech.edu/docs/API_resources.html)
она выдаёт одну составную запись на подтверждённую планету. Выгрузка сделана
19.09.2026 запросом из `scripts/fetch_source.py`: 6366 строк и 9 выбранных полей
(`pl_name`, `hostname`, `disc_year`, `discoverymethod`, `pl_orbper`, `pl_rade`,
`pl_bmasse`, `sy_dist`, `st_teff`). Снимок занимает 645308 байт; SHA-256:
`c1896ab41bafd135ad567355d350bafc0943900ec14d0be73654366f49320dab`.
CSV хранится через DVC, не через Git.

**Условия использования.** Отдельная стандартная лицензия (например, CC0)
именно для PSCompPars в документации архива не указана. [FAQ архива](https://exoplanetarchive.ipac.caltech.edu/docs/faq.html)
говорит, что опубликованные данные можно использовать в исследованиях при
надлежащем указании источника; [архив просит приводить атрибуцию](https://exoplanetarchive.ipac.caltech.edu/docs/acknowledge.html).
[Политика NASA по научным данным](https://science.data.nasa.gov/about/license)
предупреждает, что права на данные, полученные не напрямую миссией NASA,
нужно проверять отдельно. Поэтому здесь не заявляется чужая лицензия CC0 и
не публикуется исходный CSV в Git. Использованы числовые факты с указанием
источника; для иного распространения исходной таблицы нужно проверить права
первичных публикаций.

## Как создан набор

Это не переименование готового датасета: исходник — структурированная таблица,
без чатов, вопросов и ответов. `collect` проверяет наличие названия планеты и
звезды, исключает повторные названия, берёт только положительные конечные
числа и корректный год, затем строит один из шести типов вопросов: год/метод
открытия, период, радиус, масса, расстояние до системы или температура звезды.
Если выбранный тип не поддерживается записью, используется следующий доступный;
при отсутствии пригодных фактов строка исключается. В этом снимке исключений
на этапе `collect` не было. Числа выводятся с четырьмя значащими цифрами.

Планеты упорядочены по стабильному SHA-256 названия, а не по алфавиту исходного
CSV. Первые 2000 образуют v1, первые 4000 — расширенную v2. Для каждого
примера выбирается одна из пяти системных инструкций; выбор детерминирован.
`id` — хэш названия планеты, `topic` — её звёздная система. Каждый JSONL-объект
содержит ровно три сообщения: `system`, `user`, `assistant`.

После сбора идут проверка схемы с номером ошибочной строки, фильтр длин,
маскирование ПДн, точная и MinHash/LSH-дедупликация, гейт разнообразия,
разбиение целыми звёздными системами и независимая проверка контаминации.
Для near-dup отдельно сравнивается формулировка вопроса до блока вариантов:
перестановка вариантов не делает тот же вопрос новым примером. Порог в очистке
и проверке пересечений одинаков: 0.85.

| Длина ответа, p10 / p50 / p90, символы | 44 / 60 / 105 | 44 / 90 / 106 |
| Разброс длины ответа p90/p10 | 2.39 | 2.41 |
| Train / val / test | 1594 / 199 / 199 | 3178 / 397 / 397 |

В v2: 639 вопросов об открытии, 683 о расстоянии, 711 о массе, 565 о периоде,
703 о радиусе и 699 о температуре звезды. Доля крупнейшей группы — 0.15%,
доля самой частой длины ответа — 7.12%, точных повторов ответов — 0%.
Все пороги `diversity` пройдены без ослабления. Пересечения train/test по `id`,
нормализованному тексту, группе и near-dup равны нулю.

Расширение подтверждено командой `dvc metrics diff`: `rows_in` выросло с 2000
до 4000 (+2000), `rows_out` — с 1992 до 3972 (+1980), число групп — с 1771
до 3250 (+1479). Файлы метрик обеих версий зафиксированы в отдельных
Git-коммитах; сами JSONL хранятся в локальном DVC remote.

```text
$ uv run dvc metrics diff HEAD~1 HEAD --targets metrics/clean.json metrics/diversity.json
metrics/clean.json      rows_in   2000 → 4000   +2000
metrics/clean.json      rows_out  1992 → 3972   +1980
metrics/diversity.json  groups    1771 → 3250   +1479
```

## Ограничения и допустимое использование

- PSCompPars объединяет лучшие доступные значения из разных ссылок. Как
  [предупреждает архив](https://exoplanetarchive.ipac.caltech.edu/docs/API_PS_columns.html),
  составная строка не обязательно физически самосогласованна. Поэтому пример
  спрашивает об одном архивном факте, а не выводит новые физические величины.
- Архив обновляется. Контрольная сумма фиксирует конкретный снимок;
  `make source` откажется незаметно подменить его новой версией.
- Четыре значащие цифры удобны для краткого ответа, но не заменяют исходную
  научную неопределённость. У некоторых параметров нет оценки погрешности.
- Шаблонные вопросы обучают поиску и воспроизведению фактов, но не проверяют
  астрономические рассуждения. Названия методов открытия оставлены на языке
  архива, поэтому ответы частично смешивают русский и английский.
- Разбиение по звёздным системам защищает test от той же системы, но не
  гарантирует перенос на принципиально новые классы планет. Набор охватывает
  только уже обнаруженные и опубликованные объекты, а не всю популяцию.
- ПДн в научном источнике не обнаружены (0 срабатываний); отдельный тест
  проверяет маскирование телефона, почты и даты рождения на искусственной строке.
