# Пять дефектов исходного пайплайна

Числа ниже получены на закреплённом снимке NASA Exoplanet Archive и в
контрольных искусственных примерах из `make check`. Текущая версия — v2.

## 1. Данные попадали в Git

**Причина и симптом.** В исходном `.gitignore` не было `data/`; из пяти путей
`raw/clean/train/val/test` в `dvc.yaml` были объявлены выходами только три.
После обычного добавления файлов в Git крупные JSONL могли попасть в историю,
а `val` и `test` не получали версионирования DVC. Локальный remote не был задан.

**Исправление.** `data/` и локальное хранилище добавлены в правила игнорирования,
все пять JSONL объявлены выходами стадий, исходный CSV хранится через
`source/exoplanets.csv.dvc`, настроен локальный remote `dvc_remote/`.

**Проверка.** `git ls-files hw3-broken/data/` возвращает **0 файлов**;
самопроверка видит **5 из 5** выходов в DVC; `dvc push` отправил **5** новых
артефактов v2 в локальный remote. В Git есть только код, метрики и DVC-указатели.

## 2. Смена версии не пересчитывала результаты

**Причина и симптом.** Исходная стадия `collect` не зависела от
`collect.version` и исходного файла; у `clean` отсутствовала зависимость от
`data/raw.jsonl`. DVC мог повторно использовать старые результаты при смене
версии, хотя содержимое набора должно измениться.

**Исправление.** В `collect.deps` добавлен снимок CSV, в `collect.params` —
секция `collect` и пути выходов; в `clean.deps` — сырой JSONL. Все остальные
стадии теперь явно объявляют свои входы, параметры и выходы.

**Проверка.** При переключении `v1 → v2` число входных строк очистки меняется
**2000 → 4000**, выходных — **1992 → 3972**, а MD5 очищенного JSONL —
`e8ab17f4… → 3c1ca5ce…`. `dvc metrics diff` показывает прирост **+1980**
очищенных примеров и **+1479** групп. При возврате v1 результат восстанавливается.

## 3. Случайный сплит протекал между train и test

**Причина и симптом.** Функция `row_split` перемешивала строки, хотя внутри
одной звёздной системы могут быть несколько планет. Воспроизведение прежнего
алгоритма на очищенной v2 при seed 42 дало **104 общие группы** между train
и test (при нуле совпадений `id` и полного текста — поэтому эта ошибка
незаметна при поверхностной проверке).

**Исправление.** Разбиение идёт по нормализованному `topic`: все планеты одной
звёздной системы отправляются в один сплит. Стадия `split` падает при любом
пересечении; отдельная стадия `contamination` повторно проверяет `id`, полный
нормализованный вопрос, группу и near-dup с тем же порогом, что в очистке.

**Проверка.** На v2 размеры train/val/test — **3178/397/397**; все четыре
счётчика пересечения train/test равны **0**. Регрессионный тест на 60 группах
даёт разбиение **960/120/120** без пересечений.

## 4. Почти-дубли переживали очистку

**Причина и симптом.** Исходный `clean.py` заполнял множество `near` пустым
значением и не вызывал MinHash/LSH. Кроме того, перестановка вариантов ответа
может сильно уменьшить сходство шинглов всего текста, хотя вопрос остаётся тем
же: в отдельном примере исходный Жаккар был около **0.57**.

**Исправление.** После точной дедупликации включён `near_duplicates` с
параметрами из `params.yaml`. Для вопросов с явным блоком вариантов обе стадии
сравнивают формулировку до блока; порядок вариантов не меняет ключ. Один и тот
же нормализатор используется при очистке и проверке train/test.

**Проверка.** Контрольный набор удаляет **1 точный** и **1 почти-дубль**;
регрессионный тест на переставленных вариантах возвращает индекс второго
примера `[1]`. В реальной v2 удалено **28 near-dup** вместо нуля в исходном
коде (4000 → 3972 строк).

## 5. Гейт разнообразия только предупреждал

**Причина и симптом.** Исходная стадия формировала список нарушений, но при
непустом списке лишь печатала предупреждение и завершалась успешно. Поэтому
вырожденный набор мог пройти к разбиению и обучению.

**Исправление.** После записи диагностических метрик стадия возбуждает
`DiversityError` с фактическими значениями и порогами каждого нарушения.
`split` зависит от метрики `diversity`, поэтому не выполняется после падения
гейта.

**Проверка.** Искусственный набор из **1200** строк с **1** системной
инструкцией и **1** группой завершает стадию ненулевым кодом: отношение длин
ответа p90/p10 = **1.0** против порога **1.6**, одинаковая длина у **100%**
ответов против лимита **25%**. На реальной v2 гейт проходит: **3972** примера,
**5** инструкций, **3250** групп, p90/p10 = **2.41**, доля самой частой длины
**7.12%**, повторов ответов **0%**.

Итог: `make check` завершился успешно по всем **8** проверкам; два дополнительных
регрессионных теста тоже проходят.
