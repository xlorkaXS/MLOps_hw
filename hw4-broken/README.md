# ДЗ 4 — Препроцессинг: chat template, masking промпта, packing

## Что нужно сделать

1. Положить **свой датасет из ДЗ 3** в `data/train.jsonl` и `data/val.jsonl` —
   это выход стадии split, формат тот же (`id`, `topic`, `messages`).
   `make sample` собирает срез курса из parquet, которого у вас нет:
   он для преподавателя, и без файла так и скажет.
2. Поднять окружение: `uv sync`. Прогнать стадию: `make tokenize`.
   Запустить `make check` и посмотреть, что красное.
3. **Найти и исправить четыре намеренных дефекта.** Симптомы ниже. В коде
   стоят `TODO` — они рядом с дефектами, но говорят *где*, а не *что* и не *почему*.
4. Написать `docs/defects.md`: **разбор каждого дефекта** — в чём был, как
   проявлялся, как исправлен, каким числом подтверждается. Простое «починил»
   не засчитывается; проверка 8 требует файл минимум с четырьмя разделами.
5. Свериться с `dvc.yaml`: стадия `tokenize` объявлена, `deps` / `outs` /
   `metrics` согласованы с `params.yaml` — проверка 7. Перенос стадии в ваш
   DVC-пайплайн из ДЗ 3, после `split`, — по желанию, но это и есть её место.
6. Добиться зелёного `make check` — все девять. На видео сдачи должна быть
   финальная строка вместе с **отпечатком `tests/check.sh`**: он печатается
   последним и должен совпадать с выданным.

`docs/tokenize_report.md` генерируется стадией и руками не правится:
ваша задача — чтобы в нём появились честные цифры.

## Симптомы

- Модель, обученная на этом датасете, склонна повторять формулировку
  вопроса вместо ответа. Загляните, что именно попадает в лосс.
- Строка, которую видит обучение, и строка, которую увидит инференс,
  собираются в проекте по-разному. Пока никто их не сверял.
- Генерация с `batch > 1` даёт мусор в начале ответа, на `batch = 1`
  всё в порядке.
- Отчёт по датасету не отвечает на вопрос «сколько примеров не влезло
  в `max_seq_len`». А не влезает их заметная доля.

## Запуск

```bash
uv sync
make tokenize     # data/*.jsonl -> data/tokenized/ + metrics + отчёт
make check        # девять проверок — должны стать зелёными
```

Модель здесь не загружается: для токенизации нужен только `AutoTokenizer`.

## Где что лежит

```
params.yaml              единственная точка конфигурации
dvc.yaml                 стадия tokenize: deps / outs / metrics
scripts/make_sample.py   parquet курса -> JSONL, только для преподавателя
src/prompt.py            сборка chat template
src/tokenize_data.py     стадия tokenize
src/collate.py           паддинг батча
src/pack.py              packing и замер выигрыша по шагам
tests/check.sh           самопроверка
docs/defects.md          ваш разбор дефектов — его здесь нет, его пишете вы
```

## Подсказки

- Проверка 5 может остаться красной даже после того, как вы научите
  стадию считать обрезку. Это не баг проверки: посмотрите на распределение
  длин в отчёте и подумайте, какой `max_seq_len` здесь уместен.
- Проверка 1 сравнивает декодированные позиции с `messages[-1].content`.
  Если она красная — начните с того, что вообще попадает в `labels`.
- Правки `tests/check.sh` не запрещены, но меняют отпечаток — тогда покажите
  diff против выданного в `docs/defects.md`.
