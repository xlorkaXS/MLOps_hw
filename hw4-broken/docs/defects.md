# Разбор четырёх дефектов препроцессинга

Все числа ниже получены на собственном датасете об экзопланетах из ДЗ 3:
3178 примеров train и 397 примеров val. Использован токенизатор
`Qwen/Qwen3-0.6B`, `max_seq_len = 232`, режим рассуждений отключён.
Проверяющий скрипт не изменялся; его отпечаток — `f2002c8c9519`.

## 1. Промпт ошибочно попадал в обучающий лосс

**Причина и проявление.** `mask_prompt` копировал весь `input_ids` в `labels`,
а граница ответа была жёстко равна нулю. Поэтому модель получала обучающий
сигнал не только на ответе ассистента, но и на системной инструкции и вопросе.
Исходный прогон декодировал под `label != -100` строку, начинавшуюся с
`system`, хотя ожидался только ответ об экзопланете.

**Исправление.** Строка инференс-промпта собирается тем же chat template, что
и полный обучающий диалог. `prompt_token_len` находит её длину в токенах, а
`mask_prompt` записывает `-100` во все позиции до ответа. Если BPE склеивает
границу, используется уже предусмотренный запасной путь по символьным
офсетам; специальная проверка ставит границу на токене 3 для строки
`Приве` / `Привет, мир`.

**Численная проверка.** `make check` декодировал только контролируемые позиции
во всех **3178** примерах train и получил ровно ответы ассистента. Из 373970
токенов последовательностей в лосс идут **110399**, то есть 29.5%; оставшиеся
70.5% промпта замаскированы. Примеров без единого токена supervision — **0**.

## 2. Обучение и инференс использовали разные шаблоны

**Причина и проявление.** Инференс вызывал `tokenizer.apply_chat_template`, а
обучающий путь вручную склеивал строки со специальными токенами ролей.
Для Qwen3 при `enable_thinking: false` официальный шаблон добавляет пустой
think-блок в промпт. Ручная строка его не содержала, поэтому два пути
расходились уже на байте **375** контрольного диалога.

**Исправление.** Ручной шаблон и строковые специальные токены удалены.
Единственная функция `build_chat_text` теперь вызывает
`apply_chat_template` как для полного обучающего диалога, так и для
инференс-промпта, передавая одинаковый `enable_thinking` из `params.yaml`.

**Численная проверка.** Инференс-строка стала побайтовым префиксом обучающей
для всех **397** диалогов val. Поиск по `src/` не находит вручную записанных
токенов ролей, а `apply_chat_template` вызывается ровно в одном модуле —
`src/prompt.py`.

## 3. Decoder-only модель получала правый паддинг

**Причина и проявление.** В параметрах был указан `padding_side: left`, но
токенизатор его не применял, а `DynamicPaddingCollator` по умолчанию выбирал
`right`. При batch больше единицы последний токен короткой строки оказывался
pad-токеном, поэтому генерация продолжала паддинг вместо промпта. Начальная
метрика честно показала неправильное значение `padding_side = right`.

**Исправление.** Стадия устанавливает `tokenizer.padding_side` из
`params.yaml`, сохраняет это значение в `.pt` и метрики. Значение по умолчанию
коллатора изменено на `left`; `input_ids`, `attention_mask` и `labels`
паддятся с одной стороны, а для labels используется `-100`.

**Численная проверка.** Итоговая проверка одновременно сверила параметры,
`metrics/tokenize.json`, сохранённый train-артефакт и коллатор. У короткого
примера attention mask начинается с **0** и заканчивается **1**, а первая
позиция labels равна **-100**.

## 4. Обрезка последовательностей была невидимой

**Причина и проявление.** Код ограничивал `input_ids` по `max_seq_len`, но не
считал число затронутых примеров. В отчёте невозможно было понять, потеряна
ли часть ответа, и нельзя было сравнить долю потерь с заданным порогом 5%.

**Исправление.** Для каждой исходной строки сохраняются полная длина и флаг
обрезки. Метрики содержат `truncated` и `truncated_ratio` отдельно для train
и val; при превышении `truncated_warn_ratio` стадия печатает явное
предупреждение. Статистика считается до отбрасывания примеров, чтобы самые
длинные строки не исчезали из знаменателя. Отчёт отдельно показывает p50,
p90, p99, максимум и число примеров, у которых ответ исчез полностью.

**Численная проверка.** Для собственного набора длина train составляет:
p50 **119**, p90 **137**, p99 **154**, максимум **172** токена. Для val:
p50 **119**, p90 **135**, p99 **146**, максимум **171**. При
`max_seq_len = 232` обрезано **0 из 3178** train и **0 из 397** val, то есть
0.0% при пороге 5.0%; полностью потерянных ответов также **0**.

## Итоговая статистика

Packing объединяет 3178 train-последовательностей в 1855 бинов с заполнением
86.9%. При batch size 8 расчётное число шагов уменьшается с 398 до 232, на
41.7%. Итоговый `make check` проходит все девять проверок, а исходный
отпечаток проверяющего скрипта сохранён.
