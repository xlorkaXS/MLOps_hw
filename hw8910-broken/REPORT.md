## 3. Prefect и восстановление

Граф: `validate-input → retrieve-verified-existing-artifact → verify-evaluation-and-gate → atomic-publication`. Передаются только словари, URI и хеши; веса и тензоры не сериализуются как task results. Получение артефакта читает уже существующий кандидат. Подготовка реального входа валидирует JSONL и уникальные id. Ключ: SHA256 байтов и полной канонической конфигурации (версия токенизатора, его хеш для реального режима, хеш шаблона, длина, версия кода подготовки). Файловый JSON-результат хранится в workspace. Детерминированные отказы не повторяются автоматически; здесь артефакт локальный, сетевого retry нет.

| Опыт | Exit | Подготовка | Итог |
|---|---:|---|---|
| Сбой после подготовки | 1 | Completed | Указатель A не изменился |
| Неполный / чужой / отклонённый | 1 | Cached | SHA-256 указателя остался прежним |
| Сбой после accepted.json | 1 | Cached | Указатель B записан, события ещё нет |
| Повтор в новом процессе | 0 | Cached | В журнал восстановлено одно событие B |
| Повтор того же выпуска | 0 | Cached | Те же байты, без дубликата |
| Изменение байтов по тому же пути | 0 | Completed | Пересчёт подготовки; идентичность выпуска не изменилась |

Команды с exit, SHA-256 до/после, Prefect run ID и состояниями задач — `submission/flow/summary.json` и `attempts.json`. Отдельный журнал попыток допускает повтор. События выпуска уникальны по SHA256 manifest и решения (включая модель, runtime, eval). Указатель содержит release_id как запись для восстановления: если процесс остановился после замены указателя, следующий валидный запуск допишет недостающее событие. Журнал заменяется атомарно, один писатель; это не распределённая транзакция. На ошибку os.replace и NaN есть быстрые проверки. Реальная попытка: `b661fb56-a22d-4e5c-bcf3-6079a4c4fda6`, SHA-256 accepted до и после: `4589479090c00f9029021d7e78ff9efa6c34c9c03b6f1625c09811d4edb9b440`.

## 4. Проверки и три триггера

`make check`: 21 тест без загрузки весов. `make check-contract`: 13 контрактных тестов только со стандартной библиотекой. Для намеренной поломки `.venv/bin/python tools/run_mutation.py` в отдельном процессе подставляет исходный path-only cache_key. Тест инвалидации падает, exit 1; рабочий файл не меняется. Повторный `make check` — exit 0. Логи: before, after, mutation, restored.

| Событие | Действия |
|---|---|
| Изменился код | `make check`; изменение генерации/runtime → `evaluate_release.py`; документация не требует обучения |
| Изменились данные | Проверить JSONL/схему и новый ключ `flow.py`; изменение golden → повторная оценка; изменение обучающего корпуса не требует переобучения уже сохранённой модели, пока не создаётся новый адаптер |
| Новый адаптер | Закрепить артефакт и точную версию; `evaluate_release.py`; `flow.py --mode real`; старт API и smoke только для принятой версии |

## 5. API и откат

`/health` проверяет жизнь, `/ready` — прогретый backend. Во время фоновой задержки стенда — 503; реальная загрузка и начальный прогрев блокируют startup. Лимиты: body 32 КиБ, prompt ≤4000 символов, после шаблона ≤1024 токенов, max_new_tokens ровно 32, одно вычисление за раз. Невалидные HTTP-запросы отклоняются до генерации. `/debug` доступен только для STUB.

В интеграции по настоящему HTTP: A загружена, B опубликована, запрос всё ещё отвечает STUB A и сообщает ID A; после перезапуска B; после управляемого отката к ранее принятой A и перезапуска снова A. Изменение файла не перезагружает состояние. Для реальной модели второй допустимой версии нет: два отдельных запуска загрузили одну и ту же закреплённую baseline. Настоящий ответ на запрос рецепта: `{"answer":"REFUSE"}`, 7 выходных токенов, 200. Запрос с 4096 новыми токенами: 422. Фактические request_id, model_id, runtime_sha256 и времена сохранены в `submission/http/api-smoke.json`.

Откат: `bootstrap.py --workspace <workspace> --rollback <model_id>` для ранее принятой однозначной версии (один писатель); затем штатно остановить конкретный API-процесс и поднять заново, проверить /ready и /generate. Для STUB — `lab.py --workspace <workspace> rollback --to fixture-A`. Не перезаписывать report, не назначать champion вручную.

## 6. Замер после прогрева

Те же восемь промптов, max_new_tokens 32. Все 16 попыток, включая поля для ошибок и тайм-аутов: `submission/http/requests.jsonl`. Токены посчитаны по фактическим выходным ID, включая служебный EOS, если присутствует.

| Конкурентность клиента | n | Успех / ошибки | Пакет, с | Успех/с | Средняя задержка, с | Макс., с | Токены |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 | 8 | 8 / 0 | 1.613 | 4.96 | 0.202 | 0.220 | 51 |
| 2 | 8 | 8 / 0 | 1.597 | 5.01 | 0.375 | 0.417 | 51 |

Средняя серверная очередь выросла примерно с 0.000 до 0.175 с, вычисление осталось около 0.20 с. Очередь учитывает разбор запроса и ожидание блокировки; вычисление — шаблон, токенизацию, модель и декодирование, не «чистое время GPU». Замер полного JSON не даёт TTFT или ITL. На восьми запросах не оцениваю устойчивый p95. Prefill вычисляет состояния входа и заполняет KV-cache; decode последовательно предсказывает новые токены, используя этот кеш. Память кеша растёт с длиной последовательности и количеством одновременных последовательностей. Наш последовательный Transformers backend не измеряет непрерывный batching и не доказывает скорость SGLang/vLLM.

## 7. Доступ и сдача

Код, lock-файл, diff и доказательства — в репозитории. Golden/behavioral/train-index можно взять из отдельного приложения ДЗ6–7, распаковав в `hw67-broken/data/eval`. Веса не входят в Git и архив. Для реального прогона базу можно получить из HF по точной ревизии; адаптер — из исходного локального MLflow run (модельный пакет / artifacts/adapter) на Mac. При доступе к MLflow его можно загрузить стандартным MlflowClient.download_artifacts(run_id, 'model') и поместить семь файлов adapter в workspace/models/adapter. Если преподаватель не имеет доступа к локальному реестру, приложены сырые ответы, хеши и видео; веса передаются отдельно только по запросу. Локальные серверы и Colima после работы остановлены; данные и volumes сохранены.

Видео `ДЗ8_9_10_защита.mp4` приложено отдельно, вместе с архивом доказательств. Демонстрация использует сохранённые журналы настоящих команд и HTTP-ответов; STUB-опыт и реальные выводы модели подписаны раздельно.
